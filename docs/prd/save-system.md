# 存档系统 PRD

## 1. 概述

存档系统负责保存和加载游戏状态。支持手动存档、自动存档和版本兼容。实现目标是与 Godot 运行时实例结构保持一致。

关联主 PRD: [TOP_PRD.md](./TOP_PRD.md)

## 2. 存档内容

| 数据 | 描述 |
|---|---|
| 地图状态 | 当前地图、可破坏地形、事件点状态 |
| 单位状态 | 属性、位置、装备、`action_state`、`status_effects`、当前 HP/MP |
| 背包 | 队伍共享物品 |
| 金钱 | 当前持有金币 |
| 剧情进度 | 当前章节、分支与标记 |
| 已完成任务 | 已通过任务列表 |
| 设置 | 音量、分辨率、语言等设置 |

### 2.1 存档格式

```json
{
  "version": "1.0.0",
  "timestamp": 1234567890,
  "chapter": "chapter_05",
  "units": [...],
  "map_state": {...},
  "inventory": [...],
  "gold": 5000,
  "story_flags": {...},
  "settings": {...}
}
```

## 3. 存档管理

### 3.1 手动存档

- 主菜单和非战斗安全点允许手动存档
- 至少提供 10 个存档位
- 每个存档显示章节、时间、游玩时长

### 3.2 自动存档

| 触发点 | 描述 |
|---|---|
| 回合结束 | 每次 `Round End` 后 |
| 战斗结束 | 进入结算时 |
| 剧情结束 | 关键剧情段结束后 |

- 自动存档独立于手动存档位
- 自动存档位最多 5 个，循环覆盖

## 4. 存档版本管理

- 存档包含版本号
- 加载旧版本时优先尝试迁移
- 无法迁移时提示版本不兼容

### 4.1 迁移样例

当旧版本存档缺少新字段时，按版本迁移补齐默认值：

```json
{
  "from_version": "1.0.0",
  "to_version": "1.1.0",
  "changes": [
    "为所有单位补充 action_state，默认值为 Idle",
    "为所有单位补充 status_effects，默认值为空数组"
  ]
}
```

迁移原则：

- 能补默认值时自动迁移
- 会影响规则正确性的缺失字段不自动猜测
- 迁移后需重新写回当前版本结构

## 5. Godot 实现建议

- 使用 `user://` 存储存档
- 存档写入采用临时文件 + 原子替换，降低损坏风险
- 序列化对象时使用可稳定重建的纯数据结构
- 模板数据 ID 与运行时状态分离保存，避免把模板快照写入存档

## 6. 边界条件

| 场景 | 行为 |
|---|---|
| 存档文件损坏 | 提示损坏并拒绝加载 |
| 版本不兼容 | 提示版本不兼容 |
| 存档为空 | 返回存档选择界面 |
| 写入时崩溃 | 保留上一个有效存档 |
| 自动存档写入中退出 | 标记为无效并在下次启动时忽略 |
| 单位存在异常状态 | 必须完整保存 `status_effects` 的持续时间与来源信息 |
