# Godot 战棋游戏（火焰纹章风格）PRD

## 1. 项目概述

### 项目名称
Project Ember

### 项目类型
SRPG（战棋策略角色扮演）

### 技术栈

- 引擎：Godot 4.6
- 渲染：GL Compatibility
- 语言：GDScript
- 数据：JSON + Resource
- 平台：Windows / Linux / macOS / Steam
- 核心玩法形态：2D TileMap 战棋，不以 3D 物理交互为主

---

## 2. 产品目标

开发一个类似《火焰纹章》的 SRPG 战棋游戏，并保证规则适合在 Godot 4.6 中以数据驱动方式实现。

核心内容包括：

- 格子地图
- 回合制战斗
- 职业成长
- 武器系统
- 技能系统
- AI
- 剧情
- 存档
- 战斗动画

---

## 3. 核心玩法循环

```text
进入地图
→ 玩家回合
→ 单位移动
→ 攻击/技能/待机
→ 敌方 AI 回合
→ 回合结算
→ 胜负判断
→ 下一关
```

### 3.1 当前开发范围

当前阶段以“可运行的 Godot 战斗原型”为最高优先级，重点包括：

- 地图加载与格子移动
- 玩家/敌方回合切换
- 基础攻击结算
- 简单 AI
- 最小存档闭环

以下内容不属于当前 MVP 主路径，但属于后续版本规划：

- 大量剧情内容
- CG 与复杂过场动画
- 大规模职业/技能扩展
- 联机、MOD、Workshop

## 5. 单位系统

### 5.1 基础属性

| 属性 | 描述 |
|---|---|
| HP | 生命 |
| MP | 魔法 |
| STR | 力量 |
| MAG | 魔力 |
| SKL | 技巧 |
| SPD | 速度 |
| DEF | 防御 |
| RES | 魔防 |
| LUK | 幸运 |
| MOV | 移动力 |

### 5.2 状态建模

单位状态拆分为两层：

- `action_state`：`Idle`、`Moved`、`Acted`、`Dead`
- `status_effects`：`Poison`、`Sleep`、`Paralysis`、`Silence`

其中：

- `action_state` 为单值、互斥，用于回合流程
- `status_effects` 为列表，可叠加，用于异常状态与持续效果
- 同类异常状态默认不叠加，仅刷新持续时间
- 控制类异常（Sleep、Paralysis）默认同一时刻只生效一种，冲突时取最新效果

### 5.3 成长系统

角色拥有成长率：

```json
{
  "growth_rates": {
    "hp": 80,
    "str": 45,
    "spd": 55
  }
}
```

升级时按成长率随机成长。

## 8. 战斗系统

### 8.1 战斗流程

```text
攻击声明
→ 战斗前技能
→ 命中判定
→ 暴击判定
→ 伤害计算
→ 反击
→ 追击
→ 战斗后技能
→ 死亡结算
```

### 8.2 伤害公式

```text
物理伤害 = max(0, STR + WeaponMight + 武器克制伤害修正 - (DEF + 地形defense_bonus))
魔法伤害 = max(0, MAG + WeaponMight - RES)
```

### 8.3 命中公式

```text
HitRate = WeaponHit + SKL*2 + LUK + 武器克制命中修正 + 高度差修正
          - (目标SPD/2 + 目标LUK + 地形avoid_bonus)
```

高度差修正：

- 攻高守低：+10
- 攻低守高：-10

### 8.4 暴击公式

```text
CritRate = SKL / 2 + WeaponCrit
```

### 8.5 追击规则

武器重量参与攻击速度：

```text
AttackSpeed = max(0, SPD - Weight)
```

满足以下条件时可追击一次：

```text
攻击方 AttackSpeed >= 防守方 AttackSpeed + 4
```

### 8.6 顶层结算原则

为避免实现阶段口径漂移，顶层统一采用以下顺序原则：

1. 行动合法性与限制状态先判定
2. 战斗前技能先于命中/暴击/伤害判定
3. 死亡结算优先于战斗后恢复与后续展示
4. 回合结束时默认按“持续时间变化 → 持续伤害/恢复 → 技能冷却”顺序处理

更细的结算细节放在子 PRD 中定义。

## 9. 技能系统

### 9.1 技能类型

- 主动技能
- 被动技能
- 光环技能
- 反击技能

### 9.2 技能数据结构

```json
{
  "id": "double_attack",
  "name": "连续攻击",
  "type": "active",
  "trigger": "before_combat",
  "effect": {
    "type": "extra_attack",
    "value": 1
  }
}
```

### 9.3 技能触发时机

- `turn_start`：回合开始
- `turn_end`：回合结束
- `before_combat`：战斗前
- `after_combat`：战斗后
- `on_hit`：命中后
- `on_damage`：受到伤害后
- `on_kill`：击杀后
- `on_death`：死亡后

- 集成显卡

```text

```

### 地图规模

```text
最大 64x64
```

### 19.1 当前性能目标

- MVP 阶段优先保证 10x10 到 20x20 地图稳定运行
- 战斗范围高亮和寻路计算不能造成明显卡顿

## 21. MVP 最小可玩版本

### MVP 内容

- 10x10 地图
- 2 名玩家角色
- 2 名敌人
- 回合制
- 移动
- 攻击
- 胜负判断
- 基础敌方 AI
- 最小战斗 UI

### 预计开发时间

```text
按阶段推进，不承诺固定总周数
```

### 21.1 MVP 验收标准

- 玩家可从菜单进入一场战斗
- 玩家与敌方各完成至少一个完整回合
- 可完成移动、攻击、死亡、胜负判断
- 数据修改后可影响单位和武器表现
- 退出并重新进入后可从存档恢复基本战斗状态

## 22. 风险与难点

### 高风险模块

- AI
- 技能系统
- 状态管理
- 存档兼容
- 动画同步

### 常见问题

- 状态组合爆炸
- 技能冲突
- AI 卡死
- 数据耦合

### 22.1 风险应对方向

- 先用最少状态和技能验证主循环
- 先统一结算顺序，再扩展技能种类
- 先做可调试的数据驱动，再扩内容规模
