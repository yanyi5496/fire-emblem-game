# AI 系统 PRD

## 1. 概述

AI 控制敌方与友方 NPC 的行动。系统根据统一优先级和收益评估选择行动，适合在 Godot 中结合 A* 寻路与战斗模拟实现。

关联主 PRD: [TOP_PRD.md](./TOP_PRD.md)

## 2. AI 类型

| 类型 | 行为模式 |
|---|---|
| Aggressive | 主动逼近并攻击玩家 |
| Defensive | 固守区域，优先反击 |
| Support | 优先治疗与辅助友军 |
| Boss | 在统一优先级上附加关卡脚本事件 |
| Patrol | 沿预设路径巡逻 |

## 3. AI 决策优先级

```text
1. 击杀目标
2. 攻击残血
3. 攻击治疗单位
4. 占点
5. 靠近玩家
```

## 4. AI 执行流程

```text
1. 搜索目标
2. 生成候选移动格
3. 模拟可执行行动
4. 计算收益分数
5. 选择得分最高的行动
6. 执行移动、攻击或技能
```

执行候选行动时默认遵守顶层规则：

- 先检查 `action_state` 是否允许行动
- 再检查 `Sleep`、`Paralysis`、`Silence` 等限制状态
- 战斗模拟使用与 `CombatManager` 相同的结算顺序

## 5. 收益评估

```text
收益 = 击杀权重
     + 伤害权重
     + 生存权重
     + 战略权重
```

Boss、Support 等类型通过调整权重和脚本事件扩展，不改基础框架。

### 5.1 最小收益评估示例

假设敌方单位存在两个候选行动：

| 候选行动 | 击杀权重 | 伤害权重 | 生存权重 | 战略权重 | 总收益 |
|---|---|---|---|---|---|
| 攻击残血剑士 | 100 | 30 | 10 | 0 | 140 |
| 占据城堡等待 | 0 | 0 | 40 | 35 | 75 |

在该示例中，AI 应优先选择“攻击残血剑士”。

Support AI 可采用不同权重，例如：

- 治疗濒死友军：生存权重 60，战略权重 20
- 攻击非致死目标：伤害权重 20

## 6. Godot 实现建议

- 使用 TileMap 网格和 A* 寻路
- 收益评估复用 `CombatManager` 的模拟结果
- 对 Boss 行为使用数据驱动脚本事件，而不是写死分支

## 7. 边界条件

| 场景 | 行为 |
|---|---|
| 所有目标不可达 | 向最近目标推进或待机 |
| 无有效攻击目标 | 使用辅助技能或待机 |
| 路径被完全阻挡 | 等待一回合 |
| 多个目标收益相同 | 选择更安全位置；仍相同则按固定顺序 |
| 单位被控制类异常限制 | 不主动行动，仅等待或跳过 |
