# MVP 内容排期文档

## 1. 目的

本文档用于串联 MVP 阶段的策划、美术、音频、程序前置依赖，帮助团队在不改代码的前提下先完成资源与内容准备，并为后续 Godot 4.6 开发提供明确的开工顺序。

适用范围：

- 唯一地图 `mvp_map_01`
- 唯一剧情 `mvp_story_01`
- 唯一战斗关卡「山道遭遇战」

## 3. 工作流总览

### 3.1 四条并行线

| 线别 | 目标 | 主要产物 |
|---|---|---|
| 策划线 | 锁定玩法、数值、剧情、测试目标 | 数据包、数值基线、地图制作包、演出表 |
| 美术线 | 提供地图、单位、UI、立绘占位与正式资源 | Tile、Sprite、UI、Portrait、VFX |
| 音频线 | 提供 BGM/SFX 占位与正式版本 | 战斗 BGM、胜利 BGM、操作音效 |
| 程序线 | 后续使用上述输入搭建 Godot 场景与流程 | 场景、Autoload、联调、验收 |

### 3.2 总原则

- 先打通“可玩链路”，再补“演示包装”
- 先保证 P0 资源与文档可用，再做 P1 丰富项
- 一个阶段未闭环前，不建议并行扩第二关内容

## 4. 里程碑划分

### M0：文档准备完成

目标：

- 玩法规则、地图、剧情、资源、验收都已有文档输入

完成标准：

- 当前 `docs/design/` 中的 MVP 文档全部可被引用
- 无关键规格冲突

当前状态：已完成

### M1：可玩占位包准备完成

目标：

- 即使没有正式美术，也能靠占位资源完成战斗联调

必须完成：

- 3 张 Tile 占位图
- 4 个单位占位图
- 光标与范围高亮
- 中文字体
- 战斗 BGM 占位
- 基础命中/治疗/菜单音效占位

### M2：首关内容联调包准备完成

目标：

- 策划、剧情、地图、资源输入足以支撑完整首关实现

必须完成：

- 地图制作包锁定
- 数值基线锁定
- 剧情演出表锁定
- 主流程验收 Runbook 锁定

### M3：演示增强包准备完成

目标：

- 在不改核心规则的前提下，提升展示质量

建议完成：

- 主菜单背景
- Logo
- 立绘表情
- 胜利/败北 BGM
- 命中/治疗/死亡 VFX 正式版

## 5. 推荐执行顺序

### 阶段 1：锁规格

| 顺序 | 任务 | 负责人建议 | 前置依赖 |
|---|---|---|---|
| 1 | 确认 `mvp-balance-baseline.md` | 策划 | 无 |
| 2 | 确认 `mvp-map-production-pack.md` | 策划 | 数值基线 |
| 3 | 确认 `story-mvp-direction-sheet.md` | 策划/剧情 | 地图与剧情文档 |
| 4 | 确认 `mvp-acceptance-runbook.md` | 策划/测试 | 主流程文档 |

阶段完成标志：

- 首关体验目标不再频繁变更

### 阶段 2：做占位资源

| 顺序 | 任务 | 负责人建议 | 前置依赖 |
|---|---|---|---|
| 1 | 3 张 Tile 占位图 | 美术 | 地图制作包 |
| 2 | 4 个单位占位图 | 美术 | 数据包 |
| 3 | 光标与三类高亮 | UI/美术 | UI 线框 |
| 4 | 中文字体确认 | UI/程序协作 | 命名与资源计划 |
| 5 | 战斗 BGM 与基础 SFX 占位 | 音频 | 演出表 |

阶段完成标志：

- 资源生产计划中的第 1 批“开战可玩包”齐备

### 阶段 3：做演示层资源

| 顺序 | 任务 | 负责人建议 | 前置依赖 |
|---|---|---|---|
| 1 | `ui_logo` 与主菜单背景 | UI/美术 | 风格基准 |
| 2 | 角色立绘与表情 | 美术 | 演出表 |
| 3 | 命中/治疗/死亡 VFX | 特效 | 风格基准 |
| 4 | 胜利/败北/准备 BGM | 音频 | 演出表 |

阶段完成标志：

- 可做对外展示的 MVP 包装层

## 6. 依赖关系图

```text
数值基线
  ↓
地图制作包 ─→ 占位 Tile / 单位资源
  ↓
剧情演出表 ─→ 立绘 / BGM / 对话 UI 需求
  ↓
验收 Runbook ─→ 联调与测试顺序
```

## 7. 风险点

### 7.1 最容易阻塞的点

| 风险 | 影响 | 处理建议 |
|---|---|---|
| 地图规格反复修改 | 资源、剧情、联调全部受影响 | 先冻结 `mvp_map_01` |
| 数值未锁 | 攻击预览、AI、测试都不稳定 | 先按数值基线跑 1 轮 |
| UI 风格未定 | 资源交付碎片化 | 先做风格基准板 |
| 音频交付过晚 | 演示质感弱 | 先交占位音频 |

### 7.2 不建议现在就做的事

- 第二张地图
- 新职业或新武器扩充
- 复杂分支剧情
- 高精度演出动画
- 完整外包流程文档

## 8. 最小人力版本

如果当前人力很紧，可以按最小配置推进：

| 角色 | 必做内容 |
|---|---|
| 策划 | 锁数值、锁地图、锁剧情触发 |
| 美术 | 交占位 Tile、占位单位、光标高亮 |
| 音频 | 交 1 首战斗 BGM、基础操作音 |
| 程序 | 后续接入并按 Runbook 联调 |

## 9. 本周建议目标

如果要继续推进到“随时能开工”，建议本周只盯这 5 项：

1. 锁定 `mvp-balance-baseline.md`
2. 锁定 `mvp-map-production-pack.md`
3. 锁定 `story-mvp-direction-sheet.md`
4. 收齐第 1 批可玩占位资源
5. 用 `mvp-acceptance-runbook.md` 作为联调脚本基线

## 10. 结束条件

当以下条件全部成立时，说明非代码准备已足够支撑开发开工：

1. 首关地图、数值、剧情、资源文档都不再频繁修改
2. P0 占位资源列表全部有归属
3. 主流程验收脚本已经确定
4. 风格方向已有统一口径

到这个节点后，再继续投入文档的收益就会下降，应该转入 Godot 场景和资源接线阶段。
