## Context

当前项目有一个主 PRD 文档 `Godot_SRPG_PRD.md`，覆盖了 24 个章节。该文档是单一的 Markdown 文件，随着项目发展，需要按模块拆分为独立的详细 PRD 文档，便于维护、查阅和并行开发。

每个模块 PRD 的位置：`docs/prd/<module-name>.md`

## Goals / Non-Goals

**Goals:**
- 为每个模块创建一个独立、自包含的详细 PRD 文档
- 每个模块 PRD 包含：概述、数据定义、交互流程、边界条件、开发注意事项
- 主 PRD 保留为顶层概览，不删除或修改
- 模块 PRD 之间可以交叉引用

**Non-Goals:**
- 不引入主 PRD 中未定义的新功能
- 不修改已有的代码实现或数据结构
- 不涉及具体的技术实现细节（这些在 AGENTS.md 和代码中）

## Decisions

1. **文档格式**：使用 Markdown，与主 PRD 一致，便于 Git 版本管理
2. **文档位置**：`docs/prd/` 目录下，每个模块一个独立 `.md` 文件，如 `docs/prd/map-system.md`
3. **模块划分**：严格按主 PRD 的章节划分（第 4-18 章），不合并、不拆分
4. **文档结构**：每个模块 PRD 使用统一模板，包含：
   - 概述（与本模块定位和主 PRD 的关系）
   - 详细属性定义（表格 + JSON 示例）
   - 交互流程（文字描述 + 流程图）
   - 边界条件/异常处理
   - 依赖关系（引用其他模块 PRD）
   - 开发注意事项
5. **交叉引用**：使用相对路径 `./<module-name>.md` 引用同目录下其他模块 PRD
6. **顺序创建**：按主 PRD 章节顺序依次创建，每个完成后标记

## Risks / Trade-offs

- [内容偏离] → 每个模块 PRD 必须严格基于主 PRD 内容展开，如需新增内容需先更新主 PRD
- [文档不同步] → 主 PRD 更新后，模块 PRD 需同步更新
- [过度设计] → 保持合理粒度，不提前写超出当前开发阶段的内容
